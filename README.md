# BostonRobotics AdminSystem

เว็บไซต์จัดการนักเรียนและตารางเรียน ใช้ GitHub Pages + Google Apps Script + Google Sheets

## รุ่น 2.3.2 (ใช้ Apps Script API รุ่น 2.2)

- นัดในวันเดียวกันที่เวลาเริ่มและเวลาจบตรงกัน แสดงเป็นกลุ่มเวลาเดียว มีรายชื่อนักเรียนอยู่ข้างกัน ทั้งปฏิทินและรายละเอียดรายวัน
- พิมพ์ชื่อนักเรียนเพียงตัวแรกแล้วเลือกจากรายชื่อแนะนำได้ทันที รองรับปุ่มลูกศร Enter และ Escape และรวมชื่อซ้ำตามกติกาเดิม
- เมื่อเลือกนักเรียนแล้ว กด **ดาวน์โหลดตารางเรียน PNG** ในหลักสูตร / Level ที่ต้องการ ภาพมีโลโก้ BostonRobotics ชื่อ หลักสูตร Level ชั่วโมงรวม ความคืบหน้า และวันเวลาแต่ละ Session
- PNG กว้าง 1170 พิกเซล ออกแบบที่ความกว้างมือถือ 390 พิกเซล ความสูงเพิ่มตามจำนวน Session เพื่อเลื่อนอ่านโดยไม่ต้องย่อข้อความ ไม่ส่งข้อมูลไปบริการสร้างภาพภายนอก
- สถานะเรียนแล้วและความคืบหน้าคำนวณจากเวลาจบนัดตามเวลาไทย ยังไม่ใช่การเช็กชื่อเข้าเรียน
- รุ่น 2.3 ไม่เพิ่มคอลัมน์ชีต และไม่เปลี่ยน API จาก 2.2 ถ้าเคยอัปเดต Code.gs รุ่น 2.2 พร้อม Deploy แล้ว รอบนี้อัปเดตเฉพาะไฟล์เว็บได้

### ปรับภาพ PNG ในรุ่น 2.3.2

ใช้เลย์เอาต์ตามภาพตัวอย่าง 3333.png: แสดงชื่อเดียว หลักสูตรและ Level/ชั่วโมงอยู่แถวเดียวกัน คงเหลือทางซ้ายและเรียนแล้วทางขวาเหนือแถบความคืบหน้า ส่วน Session/วันที่อยู่ซ้าย เวลาอยู่กลาง ป้ายสถานะอยู่ขวา ข้อความยาวขึ้นบรรทัดใหม่ได้ และแสดง Session ครบทั้งหมด อัปเดตเฉพาะ index.html และ js/schedule-export.js ไม่ต้องแก้ Code.gs

### ปรับภาพ PNG ในรุ่น 2.3.1

จัดโลโก้และข้อความใน PNG กึ่งกลาง เอาชื่อ BostonRobotics ที่ซ้ำกับโลโก้ออก ลดตัวหนังสือทุกส่วน 4 pt และจัดสถานะเรียนแล้ว/รอเรียนให้อยู่กลางกรอบด้วยขอบเขตตัวอักษรจริง อัปเดตจาก 2.3 ด้วย index.html และ js/schedule-export.js ไม่ต้องแก้ Code.gs

## ปฏิทินและการเชื่อมต่อ

- เปิดหน้าแรกเป็นปฏิทินรายเดือน จันทร์–อาทิตย์ 6 สัปดาห์ ตามรูปแบบปฏิทินอ้างอิง
- แสดงชื่อนักเรียน เวลา หลักสูตร สีหลักสูตร วันหยุด และกรอบวันที่ปัจจุบัน
- ปุ่มเลื่อนเดือนขนาด 60 × 56 พิกเซล พร้อมปุ่มกลับเดือนนี้
- กดวันที่เพื่อดูนัดทั้งหมด และเปิดแก้ไขนัดจากปฏิทินได้
- แบบฟอร์มจัดการนัดรายนักเรียนยังอยู่ใต้ปฏิทิน เมนูอื่นยังใช้งานได้
- ไม่มีหน้าเข้าสู่ระบบ รหัสผ่าน หรือ session ของแอป อ่านข้อมูลอัตโนมัติเมื่อเปิดเว็บ
- ใช้เวลา Asia/Bangkok คำนวณชั่วโมงจากเวลาจบนัด และรักษาการตรวจเวลาซ้อน/วันหยุดก่อนบันทึก

**เมื่อใช้รุ่นนี้ ผู้ที่เข้าถึง URL ของเว็บหรือ Apps Script deployment สามารถอ่านและแก้ไขข้อมูลได้โดยไม่ใช้รหัสผ่าน รวมถึงข้อมูลนักเรียน ผู้ปกครอง และการชำระเงิน** สิทธิ์ Google ของ deployment และสิทธิ์แชร์ชีตยังเป็นการตั้งค่าแยกกัน


## การปรับปรุง Session และนักเรียนในรุ่น 2.2

- ปฏิทินแสดงเลขจาก Schedule.SessionNo โดยตรง และซ่อนรายการที่อ้างอิงนักเรียนหรือหลักสูตรไม่ครบ
- วันหยุดใช้พื้นชมพูและชื่อวันหยุดสีแดงทั้งในปฏิทินและรายละเอียดรายวัน
- นักเรียนทั้งหมดนับบุคคลที่มีนัดเรียนซึ่งผ่านเวลาจบแล้ว ส่วนกำลังเรียนนับคนที่สถานะกำลังเรียนและยังมี Session เหลือ รวมผู้ยังไม่ชำระ แต่ไม่นับทดลองเรียน พักการเรียน จบหลักสูตร และยกเลิก
- จำนวนนักเรียนที่กำลังเรียนแยกตามหลักสูตร นับคนเดียวกันครั้งเดียวต่อหลักสูตรและครั้งเดียวในยอดรวม
- เลือกนักเรียนชื่อเดียวครั้งเดียว แล้วดูประวัติเรียงหลักสูตรและ Level พร้อม Session ที่เรียนแล้ว เหลือ และยังไม่นัด
- ลงทะเบียนใหม่เลือกได้ 1–15 Session และกำหนดวัน เวลาเริ่ม เวลาจบของแต่ละ Session ก่อนบันทึกพร้อมกัน
- ตัวเลือกเวลาดึงจากคอลัมน์ TimeSlots ใน Lists โดยตรง ไม่สร้างรายการเวลาแยกในหน้าเว็บ
- ช่วงเวลาที่ซ้อนกันอนุญาตเฉพาะหลักสูตรเดียวกัน สูงสุด 3 คน ระดับต่างกันได้ นักเรียนคนเดียวกันลงซ้อนเวลาไม่ได้ ตรวจที่ backend ภายใต้ lock
- ต้องยืนยันเมื่อนัดตรงวันหยุดหรือเรียนร่วมกลุ่ม ก่อนบันทึก ระบบตรวจเงื่อนไขทุก Session ก่อนเริ่มเขียนข้อมูล
- คำขอลงทะเบียนใหม่มีรหัสคำขอเดิมสำหรับการลองบันทึกซ้ำ หากการเขียนสะดุด ระบบจะดำเนินรายการเดิมต่อโดยไม่สร้างการลงทะเบียนซ้ำ
- รักษาสูตรเดิมในชีต รวมถึงสูตร ARRAYFORMULA และสูตร SessionNo/Duration ช่องหมายเหตุที่คำนวณจากสูตรจะแสดงให้อ่านได้

## คอลัมน์ที่เพิ่มในชีตจริง

เพิ่ม **Enrollments!I1 = SessionCount** ใน BostonRobotics_CalendarV2 แล้ว เป็นคอลัมน์เก็บจำนวน Session ต่อการลงทะเบียน ข้อมูลเดิมที่ว่างจะใช้ Courses.SessionCount เป็นค่าเริ่มต้น การลงทะเบียนใหม่จะบันทึกจำนวนที่เลือกในคอลัมน์นี้

โค้ดรองรับการเพิ่มหัวคอลัมน์ SessionCount อัตโนมัติหากนำไปใช้กับชีตสำเนาที่ยังไม่มีคอลัมน์นี้ ไม่ลบหรือย้ายคอลัมน์เดิม

## ไฟล์ที่ต้องอัปเดต

บน GitHub ให้แทนที่หรือเพิ่มไฟล์ตามตำแหน่งเหล่านี้ให้ครบ:

1. `index.html`
2. `css/style.css`
3. `js/domain.js`
4. `js/app.js`
5. `css/calendar-groups.css`
6. `css/student-search.css`
7. `js/student-search.js`
8. `js/schedule-export.js`
9. `assets/boston-logo.png`

หาก Google Apps Script ยังเก่ากว่ารุ่น 2.2 ให้แทนที่ `Code.gs` ด้วย `apps-script/Code.gs` รุ่น 2.2 ด้วย เพื่อให้รองรับรายการเวลา การลงทะเบียนหลาย Session และกติกากลุ่มไม่เกิน 3 คน

## อัปเดต Google Apps Script

1. เปิด Google Sheets เดิม แล้วเลือก **ส่วนขยาย > Apps Script**
2. สำรอง Code.gs เดิม แล้วแทนเนื้อหาด้วย [apps-script/Code.gs](apps-script/Code.gs) และบันทึก
3. ตั้ง Time zone เป็น `Asia/Bangkok` รักษาการตั้งค่าอื่นของโปรเจกต์เดิม
4. เลือก **Deploy > Manage deployments > deployment เดิม > Edit > Version: New version > Deploy** เพื่อรักษา URL /exec เดิม
5. รักษา Execute as และสิทธิ์เข้าถึง deployment เดิม
6. เปิด URL /exec ต่อด้วย `?action=getHealth` ต้องได้ `success: true`, `version: "2.2"`, `authMode: "none"`
7. อัปเดตไฟล์เว็บทั้ง 9 ไฟล์บน GitHub แล้วรอ GitHub Pages เผยแพร่ จากนั้นรีเฟรชเว็บด้วย Ctrl+F5

**เพียงบันทึก Code.gs ไม่ได้อัปเดต deployment ที่เผยแพร่ ต้องเลือก New version ด้วย**

รุ่นนี้ไม่ใช้ `ADMIN_PASSWORD` หรือ `LOGIN_ATTEMPTS` แล้ว ไม่จำเป็นต้องตั้ง Script properties เหล่านี้ หากสร้าง deployment ใหม่ ต้องแก้ `API_URL` ใน `js/app.js` ให้เป็น URL ใหม่

หากพบข้อความให้ใช้ Code.gs รุ่น 2.2 แสดงว่าเว็บยังเชื่อมกับ deployment รุ่นเก่า หากพบ timeout ให้กด **โหลดข้อมูลใหม่** ระบบจะแจ้งสาเหตุจริงโดยไม่สรุปว่า API เป็นรุ่นเก่า และปิดปุ่มบันทึกจนกว่าข้อมูลทุกชุดจะโหลดครบ

## ตรวจสอบในเครื่อง

ต้องมี Node.js 18 ขึ้นไป ไม่ต้องติดตั้ง dependencies

```sh
node --test tests/*.test.cjs
node tools/preview.cjs --demo
```

เปิด http://127.0.0.1:4173 จะเห็นปฏิทินและข้อมูลจำลองทันที ไม่ต้องกรอกรหัสผ่าน การบันทึกในโหมด demo เปลี่ยนเฉพาะข้อมูลจำลองในหน่วยความจำ ไม่แตะ Google Sheets จริง

หากต้องการเรียก backend จริงให้ใช้ `node tools/preview.cjs` (ไม่มี --demo)

ชุดทดสอบครอบคลุมการเชื่อมต่อ เปิดข้อมูลโดยไม่เข้าสู่ระบบ การตรวจรุ่น deployment ปฏิทินข้ามเดือน/ปี ปีอธิกสุรทิน เขตเวลา ชั่วโมงเรียน การตรวจเวลาซ้อน วันหยุด และการรักษาข้อมูลเดิม การทดสอบกับ mock Apps Script ไม่ทดแทนการตรวจหลัง deployment จริง
