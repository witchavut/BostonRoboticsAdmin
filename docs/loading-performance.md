# ปรับความเร็วโหลดข้อมูลเริ่มต้น

หน้าเว็บตรวจ getHealth แล้วอ่านข้อมูลทั้งหกชุดผ่าน getBootstrap ใน POST เดียว ลดคำขอตอนเปิดจาก 7 เหลือ 2 และตอนกดโหลดใหม่จาก 6 เหลือ 1 คำขอ Apps Script เปิด spreadsheet ครั้งเดียวในคำขอนี้ ใช้ตัวอ่านข้อมูลเดิมเพื่อรักษาวันเวลา สูตร และ readOnlyFields ไม่มี cache ข้อมูลข้ามคำขอ

หาก deployment ยังไม่มี capability bootstrap หน้าเว็บยังเรียกข้อมูลแบบเดิมได้ หากข้อมูลชุดใดผิดพลาดจะแจ้งชื่อชุดข้อมูลและปิดการบันทึกจนโหลดครบ ห้ามตีความชุดข้อมูลที่หายไปเป็นรายการว่าง

## เผยแพร่

1. สำรอง Code.gs จาก Apps Script ที่ใช้งานจริง และเปรียบเทียบกับไฟล์ใน repository ก่อนแทนที่ หากมีการแก้ไขนอก GitHub ให้รวมการแก้ไขนั้นก่อน
2. อัปเดต apps-script/Code.gs ในโปรเจกต์ปฏิทินเดิม (ไม่ใช่โปรเจกต์การเงิน) แล้ว Deploy > Manage deployments > เลือก deployment เดิม > Edit > New version > Deploy รักษา URL และสิทธิ์เดิม
3. getHealth ต้องแสดง capabilities: ["bootstrap"] โดย version ยังเป็น 2.2 เพื่อให้หน้าเว็บรุ่นเดิมใช้งานร่วมกันได้
4. อัปเดต js/app.js และ index.html บน GitHub Pages แล้วเปิดเว็บใหม่

## เปรียบเทียบเวลา

ข้อความสถานะจะแสดงเวลาโหลดข้อมูลเป็นวินาทีและคำว่า แบบเดิม หรือ แบบรวม เวลานี้เริ่มเมื่อโหลดข้อมูลหลัง health และสิ้นสุดก่อน renderAll ไม่รวมเวลาตรวจ health หรือวาดหน้าจอทั้งหมด ใช้เวลาจากเปิดหน้าไปจนตารางปรากฏประกอบด้วย

วัดก่อนและหลังด้วยข้อมูลเดียวกันอย่างละ 3 รอบ แยกรอบแรกจากรอบโหลดซ้ำ เนื่องจากเวลาเริ่มทำงานของ Apps Script ผันผวนได้ เปรียบเทียบค่ากลาง ไม่ถือว่าจำนวนคำขอลดลงเท่ากับความเร็วเพิ่มเป็นสัดส่วนเดียวกัน ใน Network ต้องเห็น getHealth และ getBootstrap แทนหกคำขอข้อมูลเดิม

ผลวัด API จริงวันที่ 7 ตุลาคม 2026 หลังเผยแพร่ Apps Script version 7: เรียก endpoint อ่านแบบเดิมทั้งหกชุดต่อกัน แล้วเทียบ getBootstrap สลับกัน 3 รอบ ข้อมูลตรงกันทุกชุดทุกครั้ง ไม่มีการบันทึกข้อมูลจริง

| รอบ | แบบเดิม (วินาที) | แบบรวม (วินาที) |
| --- | ---: | ---: |
| 1 | 13.815 | 6.828 |
| 2 | 16.126 | 7.622 |
| 3 | 12.310 | 8.137 |

ค่ากลางลดจาก 13.815 เป็น 7.622 วินาที (ประมาณ 45%) ตัวเลขนี้เป็นเวลาเรียก API ไม่รวม health และการแสดงผลหน้าเว็บ จึงไม่ใช่คำรับประกันเวลาโหลดทุกครั้ง

เพิ่ม timestamp เฉพาะคำขอ GET ตรวจ health เพื่อไม่ใช้ URL ส่งต่อของ Google ที่อาจถูก cache จนตอบ 404 หลังเปลี่ยน deployment ส่วน POST อ่านและบันทึกยังใช้ endpoint เดิม

## ทดสอบ

node --test tests/*.test.cjs

หากสภาพแวดล้อมห้ามสร้าง subprocess ใช้ node --test --experimental-test-isolation=none tests/*.test.cjs

เพิ่มการทดสอบการโหลดรวม ความเท่าเทียมกับข้อมูลเดิม การอ่านชีตล่าสุด สูตร การโหลดไม่ครบ timeout การกู้คืนด้วย refresh และป้องกันโหลดซ้ำขณะรอ ผลในสภาพแวดล้อมพัฒนา: ผ่าน 78 จาก 81 รายการ อีก 3 รายการเป็นความคาดหวังจำนวนทดลองเรียนที่ค้างจากก่อนแพตช์นี้ (รุ่น 3.0.3 เปลี่ยนกติกาแล้วแต่ test ยังนับแบบเดิม) ไม่มีการแก้กติกานักเรียนในแพตช์ประสิทธิภาพนี้

## ย้อนกลับ

เลือก Apps Script deployment version ก่อนหน้าได้ หน้าเว็บจะกลับไปใช้การโหลดเดิมจาก capability โดยอัตโนมัติ หรือย้อน commit ไฟล์เว็บหากจำเป็น ไม่มีการย้ายหรือลบข้อมูลชีต
